# Выверка карточки: три этапа

Ведёт 🧾 Ревизор контента — его вопрос «это правда и это полно?». Этап 1 читает
вместе с ним 🧠 Методист: верный текст, по которому нельзя научиться, — тоже
находка. Роли — `docs/agent/roles.md`.

**Главное правило: находка без доказательства — не находка.** Доказательство —
это вывод команды на названной версии Python или цитата документации с адресом и
версией. «Кажется», «обычно» и «по памяти» в отчёт не идут. Память о Python —
повод проверить, а не основание.

## Режимы

- **Правка одной карточки** (новая или изменённая) — три этапа подряд, потом
  исправление и сборка.
- **Аудит группы или раздела** — три этапа независимы и идут параллельно,
  каждый своим агентом со своим списком полей. Карточки агенты не правят: они
  возвращают находки в формате ниже, а правки вносит хост одним изменением.
  Больше 40 карточек на агента не давать: выдача рвётся.

Карточки лежат в `data/cards/<группа>.json`, сборка — `data/glossary.json`.
Карточку читают из `data/cards/`, а не из сборки и не с витрины.

## Чем мерить

```bash
python3.10 / python3.11 / python3.12 / python3.13 / python3.14   # интерпретаторы окна
# 3.15 вышла 09.10.2026: её примеры исполняет матрица CI; в окне — если она установлена
python3.14 -c "import inspect, X; print(inspect.signature(X.f))"   # сигнатура
python3.14 -c "import X; help(X.f)"                                  # docstring той версии
.venv/bin/python scripts/check_examples.py --python python3.10      # гейт примеров на версии
.venv/bin/python -m glossary validate                                # правила качества
```

Документацию в окне читают из исходников CPython: прокси пускает git, а не
docs.python.org. Разреженный клон нужной ветки — только каталог `Doc/`:

```bash
git clone --depth 1 --filter=blob:none --sparse --branch 3.15 \
    https://github.com/python/cpython /home/user/python/cpython-3.15
git -C /home/user/python/cpython-3.15 sparse-checkout set Doc
```

Проверяемый диапазон — **3.10–3.15**: младшая поддерживаемая версия (на ней же
проверяет Stepik) и вышедшая 3.15. Сверять с веткой той версии, о которой
утверждение. `main` CPython — это
следующая версия, а не текущая. Пометки `versionadded` на `main` бывают неверны
у бэкпортов: прецедент — python/cpython#159013.

## Этап 1. Текст и соответствие документации

Поля: `title`, `summary`, `body`, `subcat` — обе половины, `ru` и `en`.

1. **Буквы.** Орфография, пунктуация, опечатки в именах (`isinstance`, а не
   `isintance`). Имена из кода — в обратных кавычках там, где их так пишут
   соседние карточки. Кириллица в английской половине и латиница-подмена
   (`с` вместо `c`) — находка; машинная половина — правила `language-script` и
   `mixed-script`.
2. **Правда.** Каждое утверждение сводки и разбора сверить с документацией той
   версии, о которой речь, или проверить запуском. Утверждение, которого нет в
   документации и которое не подтверждает запуск, — находка: «подаётся как факт
   то, чего в документации Python нет».
3. **Не пересказ.** Разбор говорит, на чём ошибаются: ловушки, отличие от
   соседей, когда что выбрать. Пересказ первой строки docstring — находка
   Методиста.
4. **Двуязычие.** Английская половина говорит то же, что русская, — не больше и
   не меньше. Утверждение, которое есть только в одной половине, — находка.
5. **Версии в тексте.** «С 3.12», «удалено в 3.15» в тексте обязаны совпадать с
   полями `added`, `deprecated`, `removed` — их проверяет этап 3.

## Этап 2. Соответствие примеров

Поле: `examples` — список самостоятельных блоков (#125).

1. **Исполняются.** Каждый блок — на всех версиях 3.10–3.15, где карточка живёт:
   `check_examples.py --python pythonX.Y`. Вывод обязан совпасть с каждым
   комментарием `# →`.
2. **Самостоятельны.** Блок не опирается на имена из соседнего: каждый
   исполняется в своём процессе.
3. **Пометки версий.** Блок, которому нужна версия новее `added`, начинается с
   `# Python 3.N+`. Если `removed` заполнено, нужен блок `# Python <removed>+` —
   замена или ошибка импорта (правило `removal-replacement`, #247).
4. **Ожидаемое падение названо.** Строка, на которой пример должен упасть,
   называет исключение комментарием: `print(b'a' + 'b')   # → TypeError` — исход
   «намеренно». Результат, зависящий от платформы, прав или терминала, помечается
   `→ ?` — исход «окружение». Остальные падения — находка. Соглашение — в шапке
   `scripts/check_examples.py`.
5. **Показывают то, о чём разбор.** Ловушка, названная в `body`, видна хотя бы в
   одном блоке. Пример, не связанный с разбором, — находка Методиста.
6. **Детерминированы и безопасны.** Без сети, без записи вне временного каталога,
   без зависимости от времени и порядка множества, если вывод это печатает.
7. **Устаревание.** `DeprecationWarning` в выводе законен, если карточка
   записала `deprecated` или блок сам показывает устаревшую форму (#154).

## Этап 3. Соответствие остальных атрибутов

| Поле | Как сверить |
| --- | --- |
| `id` | полное имя, как пишут в коде (`functools.reduce`, `path.glob`); методы `Path` — `path.<имя>`; без точки в начале (#244) |
| `kind` | `function` / `term` / `exception` / `construct` — по природе объекта: класс исключения — `exception` |
| `added` | замер: `hasattr` на 3.10…3.15 и `versionadded` в `Doc/` нужной ветки. `<3.0` — было ещё в Python 2. Бэкпорт в патч-выпуски — по ветке, в которую ушёл (`3.13.4` у LinkFallbackError) |
| `deprecated` | `deprecated` / `deprecated-removed` в `Doc/` и предупреждение при вызове |
| `removed` | имени нет на версии `removed` и новее; будущее удаление — по `deprecated-removed` в документации, не по памяти |
| `platforms` | пометка `Availability` в `Doc/`; `AllOS` — только если ограничений нет |
| `docs_url` | страница и якорь существуют в документации (`Doc/library/<модуль>.rst`, директива с этим именем) |
| `syntax` | совпадает с `inspect.signature` на свежей версии; у функций из C без сигнатуры — с документацией |
| `section`, `subcat`, `color_group` | как у соседних карточек того же модуля; раздел из одной карточки — ошибка `section-size` |
| `aliases`, `keywords` | то, что учащийся наберёт в поиске: русские формулировки, текст ошибки, старое имя |
| `related` | разрешаются в карточки и действительно соседи по смыслу |
| `related_errors` | исключения, которые этот объект на самом деле бросает, — проверить запуском |

## Формат находки

Одна строка таблицы на находку, сгруппированные по этапам:

| Карточка | Поле | Этап | Что не так | Доказательство | Правка |
| --- | --- | --- | --- | --- | --- |
| `zlib.error` | `body.en` | 1 | утверждает, что наследует `OSError` | `python3.14 -c "import zlib; print(zlib.error.__mro__)"` → `(error, Exception, …)` | заменить на «derives from Exception» |

Нет находок — так и написать по каждому этапу: «этап 2: 3 блока на 3.10–3.15,
расхождений 0». Пустой отчёт и непроведённый этап снаружи неразличимы.

## После находок

1. Правки — только в `data/cards/<группа>.json`, отдельным изменением о
   содержании: инструменты в него не входят.
2. `make assemble && make validate && make examples`, затем `make check`.
3. Находка, которую не исправить сейчас (например, блок для ещё не вышедшей
   версии), — в отчёт с причиной, а не молча.
4. Неточность в самой документации Python — отдельная находка с черновиком
   отчёта в CPython (прецеденты — #11, python/cpython#159013).
