# Как окно ведёт работу

**Русский** · [English](work.en.md)

> **Читатель:** агентское окно и человек, который его ведёт.

Свод ([`CLAUDE.md`](../../CLAUDE.md)) говорит, что делать нельзя. Здесь —
порядок работы: откуда берётся следующая задача и как окно поручает часть работы
агентам. Правила записаны документом: машина их не держит, держит тот, кто
ведёт окно (ответы `document` в [`.rules/bindings.json`](../../.rules/bindings.json)).

## Откуда берётся работа

Источники упорядочены, и первый непустой — это план (правило каталога 091).
Следующий источник не открывается, пока в предыдущем есть работа.

1. **Красное своё.** Красный `main`, красное или конфликтное своё изменение.
2. **Работа по правилам каталога.** Ответ `unreviewed`, правило без разбора,
   устаревший ответ «не применимо» — в `.rules/bindings.json`.
3. **Задачи трекера**, начиная с тех, у которых есть потребитель — грейдер или
   читатель витрины.
4. **Очередь содержания в машинном виде:** `make objections`, затем
   `make completeness`, затем `whatsnew.json`.
5. **Нерешённые предложения потребителя** — `pending` в `consumer-verdicts.json`.

## Волны агентов

Окно поручает агентам то, что делится на независимые куски: карточки модулей,
выверку раздела, перечитывание ответов каталогу.

- **Размер волны фиксирован: не больше пяти агентов в залпе** (031). Следующая
  волна стартует после разбора предыдущей, а не параллельно ей.
- **Темп считается от остатка, а не от желания** (033). Перед волной окно
  сверяет остаток лимита Claude и квоты GitHub (`/rate_limit`, транспорт REST)
  и выбирает число волн так, чтобы работа уложилась в остаток с запасом.
- **Зона одного агента маленькая, и у задания есть числа** (034, 117): не больше
  20 карточек на пишущего агента и не больше 40 на выверяющего, один файл
  выдачи, его формат и предел длины отчёта. Задание без чисел — находка.
- **Запреты окружения пишутся в задании** (061): «в дереве ничего не править»,
  «писать только в свою папку черновиков», какие интерпретаторы доступны, что
  сеть открыта только для git. Агент не знает правил окна, если их не
  повторили ему словами.
- **Агенты возвращают данные — файлы правит хост** (015). Выдача агента — JSON
  в черновой папке. В `data/cards/` и `.rules/` правки вносит окно, одним
  изменением.
- **Сбор и разбор — разные проходы** (054). Агенты собирают: черновики карточек,
  находки, вердикты. Что из этого принять, решает окно отдельным проходом по
  навыку `card-audit`.
- **Сборщик сверяет полученное с ожидаемым** (116). До применения окно
  сверяет: сколько единиц ждали и сколько пришло, нет ли дублей `id`, все ли
  ссылки разрешаются. Расхождение называется, а не сглаживается.
- **Разбор после каждой волны, и качество важнее механики** (060). Окно
  выборочно читает выдачу по этапу 1 навыка и прогоняет матрицу примеров;
  зелёный гейт без чтения — механика, а не разбор.
- **Сбой — перезапуск дельты** (020). Упавший или вернувший брак агент
  перезапускается на свою часть, а не вся волна.
