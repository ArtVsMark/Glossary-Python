# Фрагменты журнала изменений

Каждое изменение кладёт сюда **свой файл** вместо строки в общий
`CHANGELOG.md`. Два файла с разными именами не конфликтуют никогда — поэтому
параллельные изменения перестают спорить за один файл.

Это важнее, чем кажется: конфликтное изменение остаётся **вовсе без проверок**.
Прогон идёт по merge-коммиту, которого при конфликте не существует, и пустой
список проверок читается как «CI сломался», а не как «сливать нельзя».

## Как добавить запись

```
changelog.d/<slug>.<секция>.md
```

- `slug` — что угодно уникальное, обычно имя ветки без префикса;
- секция — одна из `added`, `changed`, `fixed`, `removed`, `internal`;
- внутри — **одна строка**: без ведущего дефиса и без имени секции, их
  подставит сборка.

Пример — файл `bilingual-cards.added.md`:

```
карточка несёт описание на двух языках, витрина переключает их без перезагрузки (#42)
```

## Команды

```bash
make changelog-check     # форма записей (тот же гейт, что в CI)
make changelog-preview   # как соберётся, ничего не меняя
make changelog-collect   # перенести в [Unreleased] и удалить фрагменты
```

Форма повторяет конвенцию соседнего проекта `ArtVsMark/Stepik-Python-Grader`
намеренно: две реализации одного алгоритма разошлись бы на первой же правке.
