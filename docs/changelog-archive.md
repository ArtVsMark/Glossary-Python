# Архив журнала изменений

Выпуски, вышедшие за окно `CHANGELOG.md`, — дословно, новые сверху. Переносит их `python scripts/changelog.py --rotate`, руками сюда не пишут.

## [1.0.0] — 2026-10-02

### Добавлено

- `glossary coverage` (`make coverage`) — покрытие официального Python карточками: инвентарь языка снимается интроспекцией интерпретатора, без сети и без разбора документации, и публикуется контрактом `coverage.json` рядом с замечаниями
- `make links` (`scripts/check_links.py`) — гейт на ссылки документации: цель ищется разметкой `](адрес` и `]: адрес` и разрешается в файл дерева, поэтому подмена цели при верной подписи больше не проходит зелёной, как проходила бы проверка подстрокой (правило каталога 166)
- `objections.json` в ветке `badges` рядом с `facts.json`: замечания к содержанию публикуются машиночитаемо, источник читает их обычным HTTP вместо ручного переноса списка в issue (#19)
- `scripts/whatsnew.py` — что появилось и исчезло между версиями Python: инвентарь снимается на каждой версии матрицы, разность соседних заменяет разбор раздела What's New, а у каждой новой сущности отмечено, есть ли о ней карточка (#19)
- Витрина умеет удалить то, что завела: кнопка «Сбросить настройки» в подвале стирает сохранённые тему и язык, а список ключей `STORE` служит источником и для записи, и для сброса (правило каталога 112).
- Восемь ответов «предмета нет» из семейства аудита получили общий рецепт опровержения: появление документа ревизии в дереве отменяет вердикт разом у всех восьми.
- Гейт `check_deadlines.py`: у порождённого процесса назван `timeout`, у работы конвейера — `timeout-minutes`. Наружной границы не было ни у одной работы `ci.yml`: зависшее задание ждало бы шесть часов по умолчанию площадки (правило каталога 100).
- Гейт `check_decisions.py`: запись решения в `docs/architecture.md` обязана называть отвергнутую альтернативу. Девять записей, заведённых до правила, освобождены планкой `tests/decisions_baseline.json`, которая движется только вниз (правило каталога 161).
- Гейт `check_journal.py`: изменение, тронувшее код или конвейер, обязано нести запись в `changelog.d/` тем же заходом, а список путей читается из git по NUL — фрагмент с кириллическим именем иначе становится невидимым (правила каталога 138 и 165).
- Гейт живой поверхности: у каждого `scripts/check_*.py` набор обязан нести и подделки, и утверждение о живом дереве, помеченное `pytest.mark.live_surface` (правило каталога 037).
- Гейт связи изменения с задачей: у изменения ровно три ответа — закрывает, делает часть с названным остатком либо освобождено причиной; четвёртого, слить и промолчать, нет (правило каталога 173).
- Ещё пять ответов «предмета нет» получили рецепт опровержения: автоматика по префиксу веток, атомарная подмена файлов, хранилище с несколькими писателями, недетерминированное в сборке витрины и мигратор схемы.
- Ещё пять ответов «предмета нет» получили рецепт опровержения: цикл опроса внешнего API, выход витрины наружу, чтение агрегированного состояния изменения, расписание-страховка у автомержа и подделка чужого интерфейса в наборах.
- Правило качества `language-script`: английская половина карточки проверяется на письменность — скопированный в неё русский текст полноту ключей проходит зелёным, а перевода не даёт (правило каталога 077).
- Свод называет срок жизни агентского окна числом — три–пять дней — и состав эстафеты при перезапуске: правка свода задним числом на запущенное окно не действует, оно работает версией, прочитанной при старте (правило каталога 006).
- Семь ответов «предмета нет» получили рецепт опровержения `refuted_by`: обращение к модели, заимствованный инструмент в пакете, исполнение чужого кода, чтение списка путей из git и собственный каталог правил теперь опровергаются командой, а не перечитыванием прозы.
- У каждого правила валидации есть подделка, на которой оно показано сработавшим: реестр `RULES` перебирается разбором набора, и девятнадцатое правило без такой подделки — находка (правило каталога 072).
- автомерж: изменение, вышедшее из черновика, ставится в очередь площадки и уезжает в `main`, как только обязательные проверки позеленели — единственная мутация GraphQL в дереве, названная поимённо (#25)
- блок «Частые ошибки» в карточке: 482 связи `related_errors` ведут на карточки-исключения — источник хранит имена, разрешение идёт без учёта регистра (#19)
- вердикт «предмета нет» несёт свой рецепт опровержения в поле `refuted_by`, и набор правил его исполняет: устаревший ответ теперь роняет проверку, а не перечитывается глазами (#25)
- версия считается по схеме семьи — тег выпуска `vX.Y.0` плюс принятые после него изменения (`scripts/version.py`); `facts.json` публикует `release` и `version`, рядом значки `release.json` и `version.json`
- гейт `scripts/check_defaults.py`: умолчание, взятое из окружения — кодировка у текстового файла и `text=True`, часовой пояс у `datetime.now()`, — отвергается разбором исходника, а не ловится прогоном (#25)
- единый значок Python (`python.svg`: версии, ОС, покрытие, выпуск, версия) рисует действие каталога `python-badge@v1.6.0` в публикации значков; публикация будится и завершением CI и python-next на `main`, а CI идёт по суточному расписанию — пуш автомержа прогонов не будит (#57)
- журнал изменений собирается из фрагментов: параллельные изменения больше не спорят за общий файл (#17)
- идемпотентный импорт карточек из клона Stepik-Python-Grader: `make import SOURCE=…`, сверка без записи — `make import-check` (#19)
- имена авторов коммитов сверяются с объявленным списком `.github/authors.txt`, а трейлер читается только из хвостового блока сообщения: прозаическое упоминание ключа больше не принимается за директиву (#25)
- исключительные утверждения нормативных документов сверяются друг с другом по названному предмету: два «только» об одном предмете внутри одного документа отвергает гейт `scripts/check_exclusive.py` (#25)
- кнопка «Скачать» в витрине: страница отдаёт свою исходную копию, снятую до правок DOM, — сохранённый файл не несёт чужой поисковый запрос и открытые карточки (#19)
- команда `glossary objections` (`make objections`) — замечания к содержанию отчётом для источника: правило, сколько карточек задето и какие именно (#19)
- набор меток репозитория объявлен в `.github/labels.yml`: метка, которую проставляет шаблон задачи или dependabot, обязана в нём быть — иначе классификация не доезжает молча (#25)
- ответ каталогу «механизма нет» разбирается надвое: поле `machine_half` называет, что из требования следует из данных целиком и почему это не построено (#25)
- ответ каталогу дополнен по 33 правилам (183–215): 8 держит гейт, 3 — прогон, 15 — текст свода с `holdable`, 7 неприменимы, у четырёх из них проба `refuted_by`; правил без ответа больше нет, без механизма по-прежнему 16 (#25)
- планка полноты `tests/completeness_floor.json` и собственный значок: неописанного не становится больше, а число может вырасти без единой правки карточек — язык прирастает сам
- правила эволюции контрактов объявлены в `docs/contracts.md`: что стабильно, что расширяемо, как добавляют новое и чего контракт не обещает — на каждый публикуемый файл (#25)
- правило качества `example-indent`: пример, открывающий блок двоеточием, обязан содержать строку с отступом — иначе код из карточки не запустится (#19)
- свод назвал порядок работы при автомерже: одна ветка — одно изменение, дописывать в открытый PR нельзя — он уезжает через минуты после позеленения (#25)
- свод назвал транспорт к GitHub: REST по умолчанию, а операции, которые окно зовёт по GraphQL, перечислены закрытым списком с причинами (#25)
- состав ролей проекта: у каждой роли свой вопрос, свой артефакт и своё возражение конкретной роли (#17)
- хук старта облачного окна собирает `.venv` на планке `requires-python` с зависимостями проверки и ставит Python 3.14 через `uv` из PyPI; сбой сети не роняет старт, вне облака хук ничего не делает (#52)

### Изменено

- `facts.json` отвечает договору фактов витрины 1.2: `repo`, `commit`, `ci`, `tests`, `python`, `checks_per_pr` выводятся из дерева, у версии и выпуска причина в `none`, публикация проверяет файл схемой витрины; прежнее `python_versions` сохранено (#49)
- Обрезка выдачи сведена в общий `glossary.reporting.truncate()`: срез и маркер обрыва отдаются одним вызовом, и показать урезанное без маркера теперь негде (правило каталога 016).
- Ответ каталогу по правилу `028` исправлен: трекер у проекта есть, и состояние комплексной задачи не ведётся прозой — оно пересчитывается прогоном `rules-inbox` из `.rules/bindings.json`.
- Ответы каталогу по правилам `037` и `144` признаны действующими: разбор прозы окном «абзац либо пункт списка» и разделение половин набора появились в дереве раньше, чем вердикты были перечитаны.
- Правил каталога, признанных действующими и не держащихся ничем, стало **22** вместо 24: закрыты `146` (живая половина набора требуется гейтом) и `173`.
- След упавшей проверки кладётся в сводку прогона таблицей «работа → исход»: логи открывает не всякий, кто чинит, а сводку видит всякий, кто открыл прогон (правило каталога 151).
- в свод проекта добавлено, что он отдаёт наружу: четыре контракта в ветке `badges` с их вопросами и названными границами измерения
- версия объявлена один раз, в `pyproject.toml`: `__version__` читается из метаданных установленного дистрибутива, а гейт `tests/test_version.py` роняет сборку и при расхождении, и при возврате литерала в исходники (правило каталога 035)
- версия проекта задаётся в одном месте: пакет читает её из метаданных дистрибутива, ручное присваивание `__version__` отвергается разбором дерева модуля (#25)
- витрина переписана под v2: переключатель RU/EN, поиск по синонимам и ключевым словам, блок «см. также», фильтр по виду карточки, ленивый рендер и системные шрифты вместо веб-шрифтов с CDN (#19)
- гейт на числа в документации распространён с README на CLAUDE.md: «маркер пропал» считается по всем размеченным файлам сразу, «значение разъехалось» — по каждому с именем файла в сообщении (#19)
- каталог правил закреплён на v1.4.0, ответ переведён на контракт 1.7 (`answers_to`, `holdable`, даты сверки), предложения — на 1.2; перечитывание исправило пять вердиктов: 042, 057, 115 и 154 держит гейт, 157 — прогон, а 142 дождался своего второго расписания (#51)
- матрица проверок доведена до Python 3.14, а 3.15-rc снимается отдельным прогоном с правом упасть (#19)
- планка Python поднята до 3.14 (`requires-python`, ruff, mypy, прогоны); предварительная 3.15 проверяется отдельным прогоном `python-next.yml` без `continue-on-error`; замер языка остаётся матрицей 3.11–3.15 и запускает пакет из дерева, а `facts.json` называет 3.15 в `python.experimental` (#53)
- полнота глоссария больше не называется покрытием и не пишется в `coverage.json`: файл затирал shields-эндпоинт покрытия кода тестами, и значок соседа ломался молча при зелёном прогоне (#23)
- правило `example-indent` заменено на `example-compiles`: пример проверяется компиляцией — тем же инвариантом, которым пользуется источник, — и это сразу нашло две синтаксические ошибки, которых прежняя эвристика не видела вовсе
- схема данных v2: карточка приняла форму источника — двуязычные `summary` и `body`, `kind`, `aliases`, `keywords`, `related`; `data/glossary.json` перестал быть источником истины и стал снимком базы знаний Stepik-Python-Grader (#19)
- у каждого кода возврата CLI описана вторая половина — чего он не означает: «нечего проверять» и «проверено, чисто» больше не читаются одинаково (#25)
- у находки в `objections.json` появилась область (`scope`) и `schema_of`, а вместо отметки времени — отпечаток снимка: находка уровня глоссария больше не теряется у потребителя, читающего только `cards`
- у публикуемых контрактов появилась общая шапка с `generated_at` и строковой `schema`: файл не исчезает при поломке прогона, а остаётся вчерашним, и без отметки времени это неотличимо от «ничего не менялось» (Glossary-Python#18)
- у разности версий названа граница честности: она отвечает на «появилось в инвентаре», а не «появилось в языке» — сущность, изменившая природу, выглядит новой (`typing.Union` в 3.14)

### Исправлено

- README больше не предлагает править `data/glossary.json` руками: файл производный, содержание правится в источнике — рецепт противоречил тому же README двумя разделами выше (#25)
- `facts.json` отвечает договору фактов витрины 1.3: `release` — серия `X.Y` (`0.1`), а не тег; публикация с тегом `v0.1.0` падала на схеме витрины, и с 2 октября значки не обновлялись
- гейт атрибуции читает `.github/authors.txt` с основы изменения, а не из рабочего дерева: личность, объявленная тем же заходом, что и подписанные ею коммиты, в силу не входит; личность с префиксом `закрыто:` лежит в истории, но новых коммитов не принимает (#25)
- запуск CLI в тестах получил явные `encoding` и `timeout`: кодировка локали у `text=True` и отсутствие дедлайна на старт — два разных скрытых умолчания (#25)
- инвентарь языка перестал зависеть от того, что ещё импортировал процесс: исключение обязано находиться в своём модуле, а не только ссылаться на него — pytest объявляет свои `Skipped` и `Failed` принадлежащими `builtins`
- набор типов событий `pull_request` объявлен явно и включает `ready_for_review`: умолчание площадки снятия черновика не включает, и изменение, открытое черновиком, добудилось бы проверок только отправкой коммита (#25)
- ответ по правилу 052 исправлен: свежесть ветки перед слиянием площадка требует, и прежняя причина утверждала обратное — предмета нет не потому, что свежесть не нужна, а потому что автоматики, обновляющей ветки, у проекта нет (#25)
- публикация значков и фактов идёт и по суточному расписанию: слияние автомержем делает токен прогона, его пуш прогонов не будит, и `facts.json` с 7 сентября стоял вчерашним (#49)
- у каждой точки входа три исхода, и третий называет предмет: пропавший каталог фрагментов, непрочитанный источник, одна выгрузка вместо двух и отсутствующий снимок больше не читаются как «нарушений нет» (#25)
- храповики качества и полноты снова исполняются: опорная версия берётся из `requires-python`, а не литералом 3.11, — после перехода CI на 3.14 оба тихо пропускались на каждой версии прогона; планка полноты сброшена на 3.14 по решению владельца (stdlib 253→270, exceptions 5→4), а сторож требует, чтобы опорная версия была среди версий CI (#53)

  механизма зафиксировано потолком и двигается только вниз.
- **Гейт на форму ответа** `tests/test_rules_bindings.py`: адрес механизма
  обязан разрешаться в существующий файл репозитория, у каждого `none`
  названа причина, `unreviewed` не допускается. Встроен в `make check`,
  CI и pre-commit.

- **Обязательная проверка `check PR`** — работа-агрегатор в `ci.yml` с одним
  постоянным именем, совпадающим с настройкой защиты ветки. Собрана с
  `if: always()` и явной сверкой вердиктов: без этого работа с `needs:` при
  падении зависимости не краснеет, а пропускается, а пропущенное защита
  засчитывает пройденным — то есть разрешает слияние ровно тогда, когда
  обязана запретить.
- **Сторожа конвейера** `tests/test_workflow_guardrails.py`: имя обязательной
  проверки сверяется с эталоном в дереве, ни одна работа не может уйти из-под
  `needs`, у каждого прогона есть ручной запуск.

### Исправлено

- **Публикация витрины падала с первого запуска.** `actions/configure-pages`
  без `enablement` требует, чтобы GitHub Pages был включён в настройках
  репозитория, а он включён не был: четыре прогона подряд заканчивались
  «Get Pages site failed: Not Found». Краснота не была видна ниоткуда — у
  прогона нет ни обязательного статуса, ни адресата, — и всё это время бейдж
  в README утверждал, что витрина публикуется. Действие теперь включает Pages
  само, а сторож не даёт вернуть зависимость от настройки вне дерева.

- **Группа `concurrency` вытесняла прогоны на разных коммитах.** Имя группы
  состояло из ссылки без коммита, поэтому прогон на новой голове PR попадал в
  одну группу с прогоном на старой: один отменялся, второй вставал в очередь,
  и результат обязательной проверки для актуальной головы не появлялся вовсе.
  Слияние вставало при зелёных проверках — отказ, неотличимый от «проверки ещё
  идут». Коммит добавлен в имя группы, сторож не даёт вернуть прежнюю форму.

- **Гейт на пустом входе зеленел.** Валидатор на глоссарии без карточек
  сообщал «ошибок 0» и возвращал успех, а сборка молча делала пустую витрину —
  ровно тот случай, который описывает правило каталога 075. Добавлено правило
  `non-empty`, сборка пустой витрины отклоняется.

- **Числа в документации переписывает сборка.** `scripts/facts.py` считает
  факты проекта из порождающих источников, README держит их внутри именованных
  маркеров, а гейт роняет сборку и при расхождении значения, и при пропаже
  самого маркера — все три условия правила 127 сразу.
- **Значки и `facts.json`** публикуются прогоном `badges.yml` в ветку `badges`:
  проект сам считает свои числа, потребитель их читает. В `main` производное
  не хранится — оно пересобирается чаще, чем идут изменения.
